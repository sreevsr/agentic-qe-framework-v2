# Reference Helpers — Optional Adoption

This folder contains team-owned helper modules (`*.helpers.ts`) that pair with the natural-language patterns defined in [`agents/shared/keyword-reference.md`](../agents/shared/keyword-reference.md) → **Grid / Aggregate Verification Patterns**.

## What's here

| File | Provides | Pairs with |
|---|---|---|
| `DataGridColumnHelpers.helpers.ts` | `verifyColumnDatesInRange()`, `sumColumnAcrossPages()`, `captureFirstRowMatching()` | Patterns 1, 2, 3 |
| `DataGridCsvVerifier.helpers.ts` | `verifyExportedCsvMatchesGrid()`, `capturePlaywrightCsvToProjectDownloads()`, `previewGridAndCsvHeaders()` | Pattern 4 |

## Why these are here (and not auto-installed)

The framework's `output/` directory is **generated content owned by the agents** — page objects, locators, specs, and test data are all created per-app by the Explorer and Builder. By convention, nothing is shipped pre-installed into `output/pages/`.

These helpers are an exception in one direction: they are **fully generic** (no app-specific selectors or logic — they work against any datagrid that satisfies the row-collector contract in `output/utils/grid-row-collector.ts`), but they were built during a customer PoC and represent ~30 KB of reusable work that would otherwise be reinvented by every team that needs CSV-vs-grid verification or multi-page column aggregation.

They live here rather than auto-installing into `output/pages/` so that:

- The `output/` invariant (generated content only) is preserved
- Adoption is an explicit, opt-in decision per team
- Teams whose apps don't need grid/CSV verification don't carry dead code

## When to adopt

Adopt these if your application has any of:

- Data grids that paginate (any style — `grid-row-collector.ts` ships 5 collector strategies: single-page, click-next, infinite-scroll, page-size-max, and numbered-page)
- A "download CSV" / "export to CSV" feature you need to verify against the visible grid
- A need to verify aggregate properties of grid data — sums, date ranges, first-row-matching capture

If none of the above apply, skip this folder entirely and skip the Grid / Aggregate Verification Patterns section of `keyword-reference.md`.

## How to adopt

1. Copy both `.helpers.ts` files into your project's `output/pages/` folder:
   ```bash
   cp reference-helpers/*.helpers.ts output/pages/
   ```
2. Ensure `output/package.json` includes `csv-parse: ^5.6.0` (used by `DataGridCsvVerifier` via `output/utils/csv-grid-compare.ts`).
3. Ensure `output/utils/grid-row-collector.ts` and `output/utils/csv-grid-compare.ts` are present — these are the underlying framework utilities that the helpers depend on. They ship at the framework root and should already be in your project setup.
4. Write scenarios using the Grid / Aggregate Verification Patterns documented in `agents/shared/keyword-reference.md`. The Enricher will recognize the NL phrasings and emit the correct `USE_HELPER:` calls; the Builder will wire them up to these helpers.

## What NOT to do

- **Do NOT modify these files inside `output/pages/`.** Framework convention: files ending in `.helpers.ts` are team-owned and the Builder never touches them. If you need a variant, copy and rename (e.g., `MyAppDataGridHelpers.helpers.ts`) — never edit the originals in place.
- **Do NOT add app-specific selectors or logic here.** These must stay app-agnostic. App-specific page objects belong in `output/pages/<AppName>Page.ts`, generated by the Builder.
- **Do NOT invent new pattern names without updating the framework.** The helper class and method name in your scenario `.md` must match exactly what the Enricher and Builder expect — see `keyword-reference.md` → Disambiguation rule 1.

## Origin

These were extracted from the Atlas QE automation PoC (May 2026). They are deliberately application-agnostic — the Atlas-specific concerns (Bootstrap `react-bootstrap` pagination markup, `react-datepicker` interaction patterns, etc.) live in the Atlas page objects and the per-app context file (`scenarios/app-contexts/atlas.md`), not in these helpers.
